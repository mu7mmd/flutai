# Owner feedback cases and precedence

This reference records the detailed intent behind the owner's October 2026 redesign corrections. It is a scoped casebook and coverage index, not permission to copy Bayin branding, backend rules, billing policy, or pixel values into an unrelated app. Apply the general rules in [design fidelity](design-fidelity.md), [scroll and overlays](scroll-and-overlays.md), and [interaction lifecycle](interaction-lifecycle.md). Read this casebook when a task involves the corresponding feature or when reviewing learned-rule coverage. Current explicit instructions override historical examples.

## Final decisions where feedback evolved

| Topic | Final decision | Earlier wording must not cause |
| --- | --- | --- |
| Inner header/body space | 16px inside scrollable content; pinned controls keep 16px above them, trailing body gap scrolls away. | Restoring the earlier 8px, a fixed outer spacer, or a second gap. |
| Filled buttons | No border for contrasting filled accents; keep shared outline for similar-to-background fills, social buttons, idle mic/media. | Removing all borders or restoring all borders. |
| Header surfaces | Shared reference-matched translucent surface, rounded and fully tappable. | Assuming either solid white or complete transparency from an isolated earlier comment. |
| Active chat/project navigation | Replace an already-open same-kind detail; local project tabs slide in place; inner routes have no main bottom bar. | Pushing repeated chat/project details after the explicit replacement clarification. |
| Composer overlay focus | Prompt taps retain focus; mode/model/credits/media sheets hide keyboard and restore appropriate prior focus on return. | Keeping keyboard static under those overlays. |
| Prompt row transition | Closed keyboard: at most two rows; opening/open: one horizontal row. Expand immediately when closing begins, with no extra resize delay. | Waiting for zero inset or for the keyboard animation to finish. |
| Drawer/profile separator | Remove it. | Continuing to improve its light-mode visibility after removal was requested. |
| Prompt surface | White in light mode; suitable resolved theme surface in dark. | A universal white color or stale tinted light prompt. |
| Menus/dialogs | Selection/form/confirmation popups become shared sheets; error/success/info alerts remain restyled dialogs; version notice is a sheet. | Keeping old popup styling as a competing presentation system. |
| Source tree/names | Promote replacement into `lib`; shared `App*` owners, explicit `BayinApp` exception. | Maintaining duplicate source/token owners or replacing persisted/API/brand strings indiscriminately. |

## Applying feedback responsibly

Build a requirement ledger for a broad task: original request, latest effective decision, affected callers, shared owner, data/action contract, and validation evidence. Read originals when the owner requests a complete review; do not claim an automatic context compaction was disabled or treat a compressed recap as a verbatim transcript. If history is unavailable, disclose the boundary. Do not infer approval from silence, a passing analyzer, or a commit carrying the owner's name. Preserve local edits, and do not generalize a temporary environment override into a config convention.

The owner's intent is consistent: exact reference fidelity, shared ownership from the second use, preserved integrations, precise interaction timing, and evidence that matches the claim. Keep implementation choices simple while covering the actual states and exceptions; neither shorter code nor a visually plausible screenshot excuses altered behavior.

### Explicit precedence and non-generalizations

C03 overrides the partial-height implementation attempted during the conversation and narrows the old blanket content-sized-sheet wording for loading-item sheets. A surface whose inner list has a constant height but whose outer extent changes does not meet it. Top safe area and keyboard constraints still belong to one layout owner; the request is not to draw interactive content under unsafe system chrome.

C01 supplements the earlier composer-overlay rule: inline recording keeps focus; actual media/mode/credits sheets keep their existing hide/restore lifecycle. C04 adds finger switching and continuous tab progress without automatically cancelling the prior scoped immediate main-navigation tap behavior. C02 refines the conditional border rule rather than replacing it with “all colored controls have borders”.

The previous pass's 85%/75%/40% choices, a specific recorder factory signature, widget names, exact animation curve/duration, API identifiers, and particular example test counts are not general design mandates. The global lesson is to preserve the user's concrete geometry/timing/permission semantics through the actual shared owners. Do not learn an incorrect intermediate implementation as the desired rule.
